# Plan 07-02: Provider Edit 交互式增强

## Tasks

### Task 1: 重写 `providerEditCommand()` 为交互式表单

<read_first>
- src/commands/provider.ts (目标文件 — `providerEditCommand()` 函数, 约 289-368 行)
- src/core/provider.ts (验证函数，保持不修改)
- src/types/index.ts (类型定义)
</read_first>

<action>
修改 `src/commands/provider.ts`，将 `providerEditCommand()` 从外部编辑器 JSON 编辑改为 inquirer 交互式表单：

1. **移除** 原有外部编辑器相关代码：
   - `import open from 'open';` — 不再需要
   - 临时文件读写逻辑（`fs.writeFile`/`fs.readFile`/`fs.unlink` 临时文件）
   - `SECURE_FILE_MODE` 常量（如果不再在其他地方使用）

2. **新增** 交互式表单流程：

   ```typescript
   export async function providerEditCommand(name: string): Promise<void>
   ```

   **步骤 A**: 验证 + 获取 Provider（保留原有逻辑）
   ```typescript
   const validation = validateName(name, 'Provider');
   if (!validation.valid) { ... }
   const provider = await getProvider(name);
   if (!provider) { ... }
   ```

   **步骤 B**: 显示当前 Provider 摘要
   ```
   ┌─ 当前 Provider ─────────────────────────────┐
     Name:        <name>
     Source:      <source>
     Type:        <type>
     Base URL:    <baseURL>
     API Key:     sk-****abcd
     Models (N):  <model1>, <model2>, ...
     Default:     <defaultModel>
   └──────────────────────────────────────────────┘
   ```

   **步骤 C**: 交互式表单编辑（inquirer 逐字段）
   - `type`: list 选择，`default: provider.type`
   - `displayName`: input，`default: provider.displayName`
   - `baseURL`: input，`default: provider.baseURL`，URL 格式验证
   - `apiKey`: **特殊处理**:
     - 先 confirm 询问 "是否修改 API Key？"（默认否）
     - 选择「是」→ password 输入框
     - 选择「否」→ 变量 `apiKey = provider.apiKey` 保留旧值
   - `models`: input，`default: provider.models.join(', ')`，至少 1 个
   - `defaultModel`: input，`default: provider.defaultModel`

   **步骤 D**: 后处理
   - 解析 models（split/trim/filter）
   - defaultModel 不在 models 中时自动添加（复用 `providerAddCommand` 中的逻辑）
   - displayName 为空时回退为 name

   **步骤 E**: 构建更新的 Provider 对象并保存
   ```typescript
   const updatedProvider: Provider = {
     ...provider,  // 保留所有原始字段（包括 createdAt, updatedAt 等）
     type: getProviderTypeFromValue(answers.type),
     displayName: answers.displayName?.trim() || provider.name,
     baseURL: answers.baseURL,
     apiKey,  // 来自步骤 C 的逻辑
     models,
     defaultModel: answers.defaultModel,
     updatedAt: new Date().toISOString(),
   };
   ```

   **步骤 F**: 显示更新摘要
   ```
   ✓ Provider '<name>' 已更新
     类型: oldType → newType
     Base URL: oldURL → newURL
     ...
   ```
   （这里根据 CONTEXT.md 中的 D-13，显示实际有变化的字段，没变化的不显示）

3. **边界情况**：
   - 所有字段默认使用当前 Provider 值，Enter 保留
   - API Key 不修改时自动填入旧值，确保 `saveProvider` 的 `validateProvider` 通过
   - 不调用 Source Template 逻辑
</action>
