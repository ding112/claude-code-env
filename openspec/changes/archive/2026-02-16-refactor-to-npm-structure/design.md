## 上下文

当前项目存在两个源代码目录 `src/` 和 `cce/`，这不符合 npm 项目的标准规范。`cce/` 目录下有完整的 `src/` 子目录结构，且包含独立的 `package.json`。根目录也有一个 `src/` 目录，可能包含核心代码。这种双重源代码结构导致开发体验混乱，不利于维护和协作。

## 目标 / 非目标

**目标:**
- 将所有源代码统一到根目录的 `src/` 目录
- 移除 `cce/` 源代码目录（保留其 README 等文档到根目录）
- 清理空的 `bin/` 目录
- 确保 `package.json` 中的所有路径配置正确
- 保持项目功能不受影响

**非目标:**
- 不改变代码逻辑或功能
- 不进行代码重构（仅迁移文件）
- 不改变项目的构建流程或外部接口

## 技术决策

### 决策 1: 合并策略
**选择:** 使用覆盖式合并，`cce/src/` 的内容覆盖到根目录 `src/`，如果有冲突需要人工确认。

**理由:** `cce/src/` 可能包含更完整或更新的代码结构，应该优先保留。

**替代方案:**
- 仅保留 `cce/src/`，删除根目录 `src/` - 可能丢失已存在的核心代码
- 保留两个目录并行 - 不符合标准结构要求

### 决策 2: `cce/` 目录处理
**选择:** 移除 `cce/` 目录，但保留其 README.md 文件到根目录（如果有）。

**理由:** `cce/` 作为源代码目录已无存在必要，但文档可能包含有用信息。

**替代方案:**
- 完全删除 `cce/` - 可能丢失文档信息
- 保留 `cce/` 作为文档目录 - 与新的单结构不符

### 决策 3: package.json 更新
**选择:** 保持根目录的 `package.json`，确保其中的 `main`、`bin` 和 `scripts` 路径正确。

**理由:** 根目录的 `package.json` 是项目的主要配置文件，应该在迁移后更新而不是替换。

**替代方案:**
- 使用 `cce/package.json` - 可能缺少现有的配置信息

### 决策 4: 构建输出目录
**选择:** 保持现有的 `dist/` 目录结构不变，只更新 TypeScript 编译配置（如 `tsconfig.json`）以反映源代码路径变化。

**理由:** 构建输出目录的标准位置通常在项目根目录，不需要迁移。

## 风险 / 权衡

- **风险:** `src/` 目录下的文件可能与 `cce/src/` 冲突，导致代码丢失
  - **缓解:** 在合并前先备份，明确列出需要人工确认的冲突文件

- **风险:** import 路径可能需要更新
  - **缓解:** 使用 TypeScript 的模块解析机制，大多数情况下路径会自动解析

- **风险:** 测试可能因为路径变化而失败
  - **缓解:** 更新测试配置中的路径引用

## 迁移计划

1. 备份当前项目状态
2. 将 `cce/src/` 下的内容合并到根目录 `src/`（处理任何冲突）
3. 更新 `tsconfig.json` 中的源代码根目录配置
4. 更新 `package.json` 中的路径引用（如需要）
5. 删除空的 `bin/` 目录
6. 删除 `cce/` 目录（保留 README.md 等文档）
7. 验证构建和开发命令仍然正常工作

**回滚策略:** 如果出现问题，可以从备份恢复项目结构。
